# T2.4 — Фронт: Login/Register, токен у localStorage, захищені роути

**Епік:** 2. Автентифікація | **Залежності:** T0.4, T2.1 | **Оцінка:** M

## Мета
Повний UI-потік автентифікації.

## Що зробити
- [x] Сторінки `/login` і `/register` (форми, inline-помилки валідації)
- [x] Зберігати `accessToken` у **localStorage** (ключ `token`)
- [x] `AuthContext` + хук `useAuth`
- [x] `ProtectedRoute`: без токена → редірект на `/login`
- [x] API-клієнт додає `Authorization: Bearer ...`
- [x] При 401 від API — очистити токен і перенаправити на `/login`
- [x] Кнопка «Вийти»

## Acceptance criteria
- Після логіну в localStorage є `token`
- Прямий перехід на `/tickets` без токена → `/login`
- Після logout токен видалений
- Помилки (невірний пароль) показуються на формі

## Playwright-тема
localStorage, preset authenticated state (storageState), негативні сценарії логіну.
