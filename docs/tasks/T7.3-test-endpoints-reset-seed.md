# T7.3 — Тестові ендпоінти reset/seed

**Епік:** 7. Службові можливості | **Залежності:** T1.3 | **Оцінка:** M

## Мета
Швидко повертати БД у відомий стан перед тестами.

## Що зробити
- [x] `TestModule`, що реєструється **тільки** при `NODE_ENV=test` (або `ENABLE_TEST_API=true`)
- [x] `POST /test/reset` — очистка таблиць + seed (з T1.3)
- [x] `POST /test/seed` — додаткові дані: `{ tickets: 5, status: "open" }`
- [x] `POST /test/users` — створити користувача з заданими роллю/паролем
- [x] Захист: окремий секрет у заголовку `x-test-key`
- [x] У production модуль недоступний (404)

## Acceptance criteria
- Після `reset` БД у стані, ідентичному першому seed
- Виклик без ключа → 401
- Ендпоінти не з'являються у Swagger у production

## Нотатки
Критично для ізоляції та повторюваності майбутніх автотестів.
