# T2.3 — Валідація DTO та єдиний формат помилок

**Епік:** 2. Автентифікація | **Залежності:** T0.3 | **Оцінка:** S

## Мета
Передбачувані відповіді API, зручні для UI і тестів.

## Що зробити
- [ ] Глобальний `ValidationPipe` (`whitelist`, `forbidNonWhitelisted`, `transform`)
- [ ] DTO з `class-validator` для auth (email формат, пароль ≥ 8 символів)
- [ ] Глобальний `ExceptionFilter` з єдиним форматом:
  ```json
  { "statusCode": 400, "error": "Bad Request", "message": ["..."], "path": "/auth/login", "timestamp": "..." }
  ```
- [ ] Повідомлення про помилки зрозумілі людині

## Acceptance criteria
- Усі помилки (валідація, 401, 403, 404, 500) мають один формат
- Некоректний email → 400 із зрозумілим повідомленням
- Стек-трейс не потрапляє у відповідь у production
